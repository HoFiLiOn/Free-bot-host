Long Polling

The runtime uses long polling via getUpdates to receive messages directly in the browser. No server required.

// Internal polling loop
while (running) {
  const updates = await getUpdates(offset);
  for (const update of updates) {
    router.dispatch(update);
  }
}
⑂

Router

The router matches incoming updates against registered handlers using commands, text patterns, and regex.

// Route matching priority:
// 1. Exact command match (/start)
// 2. Regex pattern match
// 3. Default fallback handler
⚙

Handlers

Write handler functions that receive the message context and can reply using the built-in API.

bot.onCommand('/hello', (msg) => {
  bot.reply(msg, 'Hello, ' + msg.from);
});

bot.onText(/hi/i, (msg) => {
  bot.reply(msg, 'Hey there!');
});
✈

API Methods

Available methods for interacting with Telegram:

bot.reply(msg, text)
bot.sendMessage(chatId, text)
bot.sendPhoto(chatId, url, caption)
bot.sendSticker(chatId, stickerId)
bot.editMessage(chatId, msgId, text)
⚠

Limitations

Since bots run in the browser:

  • Bot stops when tab is closed
  • Only one instance per token
  • Data is stored in localStorage
  • CORS may affect some API calls
